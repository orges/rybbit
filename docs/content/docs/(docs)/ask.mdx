---
title: Ask
description: Ask questions about your analytics in plain language and get answers grounded in your data
---

Ask is a chat inside Rybbit that reads your data and answers questions about it. Open it from **Product Analytics → Ask** in the sidebar.

It is not a generic chatbot with your numbers pasted in. Every figure it shows comes from a tool call against the Site you are asking about, and the call is shown to you: the question, the arguments, how long it took and what came back. If it cannot see something, it tells you instead of guessing.

## Asking questions

Type a question in the composer and press Enter (Shift+Enter for a new line). Threads are saved per user and per Site, so you can start an investigation, leave it, and pick it up later from the rail on the left.

Ask understands the range you are looking at. Ask while the dashboard is on "Last 7 days" and "how are we trending" means the last 7 days. When you name a period yourself — "yesterday", "last week", "the 30th" — it uses that instead, including in a Site's timezone.

Filters in the dashboard apply to the question too, and the answer records which filters were in effect, so a surprising number can always be traced back to the view it came from.

Questions it can answer well:

- "How is traffic trending compared to the previous period?"
- "Which pages get the most views but the worst bounce rate?"
- "What are the top custom events today, and did any of them start this week?"
- "Where did we lose people in the signup funnel?"
- "Show me sessions where people hit a 500 error, longest first."
- "What is our day-7 retention?"

It can also write SQL when no structured tool fits, over a read-only view of your own events.

## What it shows

Answers arrive as you watch them being written, with the model's reasoning and every tool call listed above the text. Tables and charts are rendered from the query results, not described: pick the column that labels each point and the number to plot, and the chart is drawn with the same components as the rest of Rybbit.

Under each answer you can copy it, retry it with the same question, and rate it. Retrying replaces the previous answer rather than adding a second one.

To ask a different question from the same point, hover one of your own questions and click the pencil. It comes back to the composer, and sending it replaces that question and every answer after it — so a wrong assumption three questions back is fixed in one edit rather than by starting a new thread. Editing the first question renames the thread to match.

Any figure in an answer that is not in the tool results is listed under it. Usually that is the model's own arithmetic, but it is flagged rather than passed off as data.

## Teaching it about your site

Some context is not in the data: what a "signup" means internally, which campaign matters, which outage you are still explaining. Send `/remember` followed by a note and it is included in every future question on that Site.

```
/remember Signups are the demo_request event, not the signup button click
```

Run `/usage` in any thread to see how many tokens that conversation has used.

## Configuration

Ask is off until an OpenAI-compatible chat completions endpoint is configured. Set these in `.env` and restart:

```bash
# Any OpenAI-compatible endpoint. Leave OPENROUTER_API_URL unset to use OpenRouter.
OPENROUTER_API_URL=http://your-gateway:8317/v1/chat/completions
OPENROUTER_MODEL=your-model
OPENROUTER_API_KEY=your-key
OPENROUTER_REASONING_EFFORT=medium
# Tried in order when the primary model is rate-limited or cooling down
OPENROUTER_FALLBACK_MODELS=backup-model-1,backup-model-2
```

The model needs tool calling and streaming. Every answer costs tokens and a few ClickHouse queries; on a busy Site, a long investigation can run a dozen queries.

## Safety

Ask is read-only. It cannot create dashboards, change goals or flags, or modify anything — if you ask, it will say so. It only ever sees Sites your user already has access to, and the custom SQL it can run is restricted to a read-only view of those Sites with a row cap and a time limit.
